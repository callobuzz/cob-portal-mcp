What it does

The agent proposes. A person decides.

A good agent can plan work, write a test plan or break a goal into tasks. The portal is where a team tracks that work. This server connects the two and keeps a person in charge.

1 · Read

The agent reads

It lists tasks, templates and categories. It reads one task with its steps, answers and notes.

2 · Draft

The agent proposes

It sends draft tasks, as a main task with sub-tasks, or a test plan as a check list draft. It can also write a note on a task.

3 · Approve

A person decides

The drafts wait in the portal. A person approves or rejects them and chooses who gets each task.

Safety model

Drafts and notes only. Nothing else.

The server runs on your computer. The key sets what the agent can reach. See SECURITY.md to report a problem.

  • It runs on your computerThe server is a local program. The agent talks to it over stdio, and it talks to the portal.
  • The key stays in the headerThe server sends the key only as an Authorization: Bearer header. It never writes the key to a log, an error or a URL.
  • The key acts as you, cut to its scopesA key never has more rights than the person who made it. The server offers only the tools its scopes allow.
  • Drafts and notes onlyThe agent cannot approve, assign, change a task, pay, send mail or delete.
  • A person approves every draftNothing becomes a task until a person approves it in the portal. That person decides who gets it.
  • Revoke a key at any timeOpen the portal Profile page and revoke the key. It stops working at once.
Install

Make a key. Add the server.

You need Node.js 22 or newer. npx downloads the server from GitHub and starts it. Nothing is built on your computer.

  1. Make a key

    Sign in to the portal with two-step sign-in (2FA) on. Open Profile, then API keys. Choose the scopes and how long the key lasts. Copy it at once. The portal shows it one time.

  2. Add the server

    Use one of the snippets below. Set COB_PORTAL_URL and COB_PORTAL_KEY. The Profile page also shows a block with both values filled in (“Copy MCP setup”).

  3. Check it

    Ask the agent to run whoami. It answers with your name, the key name and its scopes.

A folder copy

instead of npx

Clone the repository. Then use node <path>/dist/cli.js in place of npx -y .... On Windows write the path with forward slashes, for example J:/callobuzz/mcp-servers/cob-portal-mcp/dist/cli.js.

Why it needs no build

The built files in dist/ are committed, and bin points at dist/cli.js. npx installs the two runtime packages (@modelcontextprotocol/sdk, zod) and runs it. There is no prepare script.

VariableNeededMeaning
COB_PORTAL_URLyesThe portal address: https://portal.callobuzz.com. No trailing slash.
COB_PORTAL_KEYyesA personal key that starts with cob_. The server sends it only as an Authorization: Bearer header.
COB_PORTAL_TIMEOUT_MSnoHow long to wait for one portal answer. Default 30000. Minimum 1000.
Tools

Eleven tools. Offered by scope.

At start the server calls GET /api/v1/me and offers only the tools whose scope the key has. whoami needs no scope. Every POST carries a new Idempotency-Key, so a repeated call does not make a second draft.

ToolScopeWhat it does
whoaminoneShows the person, the key name, its scopes and its end date.
list_taskswork:readLists tasks (scope mine or team, status, limit, category, parent_id for sub-tasks).
get_taskwork:readReads one task with its steps, answers, notes, category, parent and sub-task count.
list_templateswork:readLists the published task templates, with their category.
list_categorieswork:readLists the task categories the portal offers.
get_check_resultschecks:readReads the test runs and skips of a check list task. File names only.
add_comment writework:commentWrites a note on a task. The note is marked as written through the key.
draft_tasks writework:draftSends a batch of draft tasks. A batch can hold main tasks with their sub-tasks.
draft_checklist writework:draftSends a test plan (plan JSON) as one draft with a check list.
list_draftswork:draftLists the draft batches you sent.
get_draftwork:draftReads one draft batch, with the state, category and parent of each draft.
draft_tasks

A main task with sub-tasks

Each draft takes title, and optionally templateKey or body, notes, priority, dueAt, category and doneWhen (lines). Give the main task a ref. Each sub-task names it in parentRef and comes after it in the list. Or use parentId to hang a draft under a task that already exists.

On approval

The tree stays

A sub-task takes its main task's category when it has none. When the admin approves the batch, the main tasks go to the person or pool the admin picks. The sub-tasks can wait, so the admin gives each one later.

Scopes

Four scopes. Choose the least.

Choose the scopes when you make the key. A key acts as you, cut down to its scopes. It never has more rights than you.

ScopeWhat it allows
work:readRead tasks, task templates and task categories.
work:draftSend draft tasks and check lists for approval. Read your draft batches.
work:commentWrite notes on tasks.
checks:readRead check list results.

When a call fails, the agent gets the portal's error code, its message and every details path. 401: the key is wrong, ended or revoked, so make a new key. 403: the key lacks a scope, so make a new key with the scope. 429: too many calls, so wait a minute.

Prompts

Two prompts that teach the format.

Each draft waits for a person to approve it in the portal.

Prompt

write_test_plan

Optional subject. It explains the plan JSON format (areas, cases, id, title, priority, device phone|laptop|both, url, preconditions, steps, expected, screenshot) and the writing rules. Then the agent sends the plan with draft_checklist.

Prompt

plan_growth_work

Optional goal and category. It explains how to plan business work as main tasks with sub-tasks, in the portal's words. One result per task, "What to hand in" in the notes, a doneWhen a reviewer can check, numbers as starting values. Then the agent sends it with draft_tasks.

FAQ

Honest answers.

Short answers to the questions people ask first.

Can I use it without a portal account?

No. The server is a client of the Call O Buzz portal API. It needs a portal address and a personal key from a real account. There is no hosted fallback.

Can the agent approve its own drafts?

No. The agent can only make drafts and notes. A person must approve every draft in the portal, and that person decides who gets the task.

Where does my key go?

The server sends the key to the portal as an Authorization: Bearer header and nowhere else. It never writes the key to a log, an error or a URL. Keep the key out of files you commit.

How do I stop an agent?

Open the portal Profile page and revoke the key. It stops working at once. Make a new key when you want to start again.

Why do I see fewer tools than the table shows?

The server offers only the tools whose scope the key has. Make a new key with the scope you need. whoami shows the scopes of the key you use.

Does a repeated call make a second draft?

No. Every POST carries a new Idempotency-Key for each tool call, so a repeated call does not make a second draft.

How do I report a vulnerability?

Do not open a public issue. Follow SECURITY.md.
